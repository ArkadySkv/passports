# Отчет: Постобработка OCR паспорта РФ

## 1. Введение и стратегия
Задача имеет асимметричную функцию потерь: ложное принятие (False Accept) обходится значительно дороже ложного отклонения (False Reject). Поэтому была выбрана консервативная стратегия: **принимаем документ только если он прошел строгий AND-фильтр**. Цель — обеспечить абсолютный `0` ошибок среди принятых документов.

## 2. Исследование данных (EDA)
В процессе анализа `train_predictions.jsonl` и `train_labels.jsonl` были выявлены следующие паттерны ошибок OCR:
1. **Пропуски полей:** `null` в критических полях (например, `Middle_name_ru`) — легко отсекаются.
2. **Ошибки форматов:** Неверные форматы дат, лишние символы в коде подразделения (`382-015` вместо `582-015`).
3. **Обрезка строк (Truncation):** Модель часто теряет конец строки (например, `ОТДЕЛ УФМС РОССИИ ПО ПЕНЗЕНСКОЙ` вместо `...ПЕНЗЕНСКОЙ ОБЛАСТИ...`).
4. **"Тихие" галлюцинации:** OCR путает визуально похожие символы (`О` и `С`, `М` и `Н`, `Т` и `Г`, `А` и `Л`) с уверенностью 99.9%. Примеры: `БЕНДАСОР` вместо `БЕНДАСОВ`, `ТАТЬНА` вместо `ТАТЬЯНА`.

## 3. Архитектура решения (`postprocess.py`)
Решение представляет собой каскад проверок. Если хотя бы одна проверка не пройдена — документ отклоняется:
*   **Валидация форматов:** Проверка кода подразделения по справочнику `subdivisions.csv`, проверка 10 цифр лицензии, проверка кириллицы в именах.
*   **Логическая валидация:** Дата выдачи больше даты рождения, возраст на момент выдачи ≥ 14 лет, год не выходит за разумные пределы (1900–2026).
*   **Проверка обрезки (Dictionary Prefix Check):** Если распознанное название `Issue_organization_ru` является строгим префиксом более длинного названия из справочника для этого кода — документ отклоняется (ловит обрезанные строки).
*   **Специфичные эвристики:** Регулярные выражения для отлова известных галлюцинаций (невозможные сочетания букв: `Л`+согласная, `НР`, `ХБ`, `СВИЧ` в отчествах, отсутствие пробела после сокращения `ОБЛ.В`).

## 4. Калибровка порогов уверенности (Tuning)
Использовался скрипт `tune.py` для сеточного поиска порогов `field_conf` (уверенность в поле) и `char_conf` (минимальная уверенность в каждом символе строки).
*   Попытка использовать MRZ (машиночитаемую зону) для кросс-валидации не удалась из-за различий в правилах транслитерации в датасете.
*   При снижении `char_conf` до `0.8` проскакивает 155 ошибок.
*   При снижении `char_conf` до `0.99` всё еще проскакивает 21 ошибка (например, перепутанные годы `2001` и `2007`, буквы `Я` и `Л`).
*   Написание регулярных выражений под каждую такую ошибку ведет к переобучению (overfitting). На test нейросеть сгенерирует новые опечатки.
*   **Итоговое решение:** Установлен порог `char_conf = 1.0` (требование 100% уверенности OCR в каждом символе). Это отсекает все галлюцинации.

## 5. Результаты
*   **На train:** Принято 126 документов из 3000. **Ошибок: 0**.
*   **На test:** Сгенерирован файл `answers.jsonl`. Принято **142** документа из 2000.
